engine.response

Fire crews: the response resources the incident commander dispatches.

Crews start at the fire station, travel to a target asset, then for a fixed number of ticks suppress a limited number of cells per tick around it: first fire inside the asset, then fire close to it, then a wet line next to the fire, then the structure itself (pre-wetting). Capacity is deliberately limited so the commander has to prioritise.

CREW_NAMES = ['Engine 1', 'Engine 2', 'Ladder 1', 'Engine 3', 'Rescue 1', 'Engine 4', 'Tanker 1', 'Engine 5', 'Brush 1', 'Engine 6', 'Ladder 2', 'Engine 7']
MAX_CREWS = 12
@dataclass
class Crew:

A fire crew that the incident commander sends to an asset.

Its status cycles available -> en_route -> working -> available.

Attributes:
  • id: Crew index (0-based), its position in ResponseManager.crews.
  • name: Radio name from CREW_NAMES (e.g. "Engine 1").
  • x: Position along x, in cells. Crews start at the centre of the station cell and stay where they finished their last job.
  • y: Position along y, in cells.
  • status: "available", "en_route" or "working".
  • target: Id of the asset the crew is assigned to; None when available.
  • origin: Position (x, y) the current trip started from.
  • travel_total: Ticks the current trip takes (at least 1).
  • travel_left: Ticks left until arrival (reported as eta).
  • work_left: Ticks of work left at the target before the crew is released.
  • assignment_cells: Cells treated during the current assignment.
  • cells_suppressed: Cells treated since the crew was created.
  • dispatches: Number of times the crew has been dispatched.

class ResponseManager:

The fire crews of a city incident: dispatch, travel and suppression work.

Each tick step moves en-route crews toward their target asset and lets working crews treat up to CAPACITY cells around it. With auto set, free crews are also sent to the most urgent priorities without waiting for the commander.

Attributes:
  • SPEED: Cells a crew travels per tick.
  • WORK_TICKS: Ticks a crew works at a target before it is released.
  • CAPACITY: Cells a crew can treat per tick.
  • RADIUS: Working radius (cells) around the target asset's site.
  • n: Number of crews (0 to MAX_CREWS).
  • station: Cell (x, y) of the fire station, where the crews start.
  • auto: Whether free crews are dispatched automatically each tick.
  • crews: The crews, indexed by crew id.
  • dispatch_count: Dispatches since the last reset.
  • cells_suppressed: Cells treated by all crews since the last reset.

def dispatch( self, asset_id: int, city: engine.CityModel) -> Crew | None:

Send the nearest available crew to an asset; None if every crew is busy.

The nearest crew has the shortest city-block distance from its current position to the asset's centre. The trip takes that distance divided by SPEED, rounded up (at least 1 tick). The dispatch is written to the city's event log.

Arguments:
  • asset_id: Id of the target asset (index into city.assets).
  • city: The city model that holds the asset and the event log.
Returns:

The dispatched crew, now "en_route", or None if no crew is available.

def step( self, city: engine.CityModel, grid: engine.Grid) -> list[tuple[int, int]]:

Advance every crew one tick; returns the cells to suppress this tick.

With auto set, free crews are first dispatched to the top priorities (any level but low) that have no crew yet. En-route crews move in a straight line toward the asset's centre and start WORK_TICKS ticks of work on arrival. Each working crew picks up to CAPACITY cells within RADIUS of the asset's site: fire on the asset first, then other fire; if that area has fire or the asset is within city.THREAT_R of it, also unburned fuel next to the fire and then the asset's own unburned fuel (pre-wetting). Within each tier, cells nearer the asset's centre come first. A crew is released when its work time is over, or when it finds nothing to treat and the fire is farther than city.ALERT_R from the asset. Arrivals and releases are written to the city's event log.

Arguments:
  • city: The city model (assets, fire distances, priorities and event log).
  • grid: The fire grid whose cell states and fuel are read.
Returns:

The (x, y) cells to suppress; no cell is listed twice.
