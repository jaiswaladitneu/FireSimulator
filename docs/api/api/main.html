api.main

FastAPI application: scenario management and playback control (Epic E2).

This is the control surface other components and the UI use. It wraps the simulation (a Facade over the engine and, for towns, the city layer) and keeps scenarios in a repository. A single active session is held for simplicity.

City scenarios add the incident-command features: the town map, people at risk, priorities, fire-crew dispatch, and an incident history (Epic E6) that records every finished city incident for the admin dashboard.

Module state: scenarios keeps the saved scenarios in memory, and incidents keeps the incident history in data/incidents.json under the repository folder (set the FIRESIM_INCIDENTS_FILE environment variable to use another file, or to an empty value or :memory: to keep it in memory). A re-entrant lock lets one request at a time touch the live session. Every route is also served under /api (ApiPrefixMiddleware), and the built UI is served from / when FIRESIM_STATIC_DIR names an existing folder (mount_ui).

class ApiPrefixMiddleware:

ASGI middleware that serves /api/<path> as /<path>.

The UI always calls the API under /api. In development the Vite proxy strips the prefix; when this app serves the built UI itself (the Docker image), this middleware does the same, so one UI build works in both setups.

class IgnitionPointIn(pydantic.main.BaseModel):

A cell where the fire starts, as given in a scenario request.

Attributes:
  • x: Column index of the cell (x grows to the east).
  • y: Row index of the cell (y grows to the south).
  • tick: Tick of the ignition (default 0); it is stored with the scenario, but every point is ignited when the simulation is built.
x: int = PydanticUndefined
y: int = PydanticUndefined
tick: int = 0
class ScenarioIn(pydantic.main.BaseModel):

Request body of POST /scenarios: the parameters of a new scenario.

Attributes:
  • name: Display name of the scenario.
  • width: Map width in cells (1 to 400, default 200; city maps need at least 48).
  • height: Map height in cells (1 to 400, default 200; city maps need at least 48).
  • seed: Random seed (default 0); the same parameters and seed reproduce the same run.
  • wind_direction: Direction the wind blows toward, in degrees clockwise from north (default 90, east).
  • wind_speed: Wind speed in km/h (default 15).
  • ignition_points: Cells where the fire starts; points outside the map or with nothing to burn are ignored. A city scenario without any gets a default point upwind of the town.
  • map_type: "wildland" (default) or "city" (a town with people and fire crews).
  • hour: Local hour the incident starts (0 to 23, default 14); in city scenarios it drives how many people are in each building.
  • crews: Number of fire crews (0 to 12, default 4); city scenarios only.
  • auto_dispatch: Whether crews dispatch themselves to the top priorities from the start (default False); city scenarios only.
name: str = PydanticUndefined
width: int = 200
height: int = 200
seed: int = 0
wind_direction: float = 90.0
wind_speed: float = 15.0
ignition_points: list[IgnitionPointIn] = PydanticUndefined
map_type: Literal['wildland', 'city'] = 'wildland'
hour: int = 14
crews: int = 4
auto_dispatch: bool = False

class BatchIn(pydantic.main.BaseModel):

Request body of POST /incidents/simulate: a batch of headless city incidents.

Attributes:
  • count: Number of incidents to run (1 to 20, default 5).
  • size: Side of each square town map, in cells (48 to 128, default 80).
  • max_ticks: Tick limit per run (50 to 3000, default 800); a run still burning at the limit is recorded with outcome "time_limit".
  • seed: Seed for drawing the run conditions; None (default) draws new ones every time.
count: int = 5
size: int = 80
max_ticks: int = 800
seed: int | None = None

{"status": "ok"}.

@app.post('/scenarios', status_code=201)
def create_scenario(body: ScenarioIn) -> dict:

Create a scenario and make it the active simulation.

Builds the map and engine and replaces any previous live session; the new simulation starts idle at tick 0, and its run counts as a new incident. The scenario is also saved so it can be listed and replayed. A city scenario without ignition points gets a default ignition upwind of the town, and the saved scenario keeps the points actually used.

Arguments:
  • body: Parameters of the new scenario.
Returns:

{"id": <scenario id>, "name": <scenario name>}, with status 201.

Raises:
  • HTTPException: 422 if the engine rejects the scenario, e.g. a city map with a side shorter than 48 cells; nothing is saved and the live session is kept.
@app.get('/scenarios')
def list_scenarios() -> list[dict]:

List the saved scenarios.

Scenarios are kept in memory, so the list starts empty after an API restart.

Returns:

One dict per scenario, in creation order, with id, name and payload (the parameters the scenario was created with).

@app.get('/scenarios/{scenario_id}')
def get_scenario(scenario_id: str) -> dict:

Get one saved scenario.

Returns its id, its name and the parameters it was created with.

Arguments:
  • scenario_id: Id returned by POST /scenarios.
Returns:

The scenario as {"id", "name", "payload"}.

Raises:
  • HTTPException: 404 if no scenario has this id.
@app.delete('/scenarios/{scenario_id}', status_code=204)
def delete_scenario(scenario_id: str) -> None:

Delete a saved scenario.

Only the saved record is removed; a live simulation built from it keeps running. Responds with 204 No Content.

Arguments:
  • scenario_id: Id of the scenario to delete.
Raises:
  • HTTPException: 404 if no scenario has this id.
@app.get('/scenarios/{scenario_id}/replay')
def replay_scenario(scenario_id: str, max_ticks: int = Query(2000)) -> dict:

Deterministically replay a saved scenario and return its per-tick timeline.

Runs are reproducible (seeded RNG + procedural map), so a saved scenario replays to the exact same sequence of states without the original live session. Each frame is the cell-state counts at that tick (plus people and buildings for city scenarios).

The replay uses only the saved parameters (including ignitions added before the first tick); spot fires, dispatches, suppression and auto-dispatch changes made during the live run are not replayed.

Arguments:
  • scenario_id: Id of the saved scenario.
  • max_ticks: Maximum number of ticks to simulate (1 to 10000, default 2000).
Returns:

A dict with scenario_id; ticks (ticks simulated); final_state ("completed" if the fire went out, "running" if max_ticks was reached first); and frames, one for each tick from 0 to ticks, each with tick and counts (cells per state) plus, for city scenarios, city with at_risk, casualties, evacuated and buildings_destroyed.

Raises:
  • HTTPException: 404 if no scenario has this id; 422 if the engine rejects the saved scenario.
@app.post('/simulation/play')
def play() -> dict:

Start or resume the active simulation.

An idle or paused simulation becomes running; in any other state nothing changes. Playing does not advance time by itself: each POST /simulation/tick then advances one tick.

Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.post('/simulation/pause')
def pause() -> dict:

Pause the active simulation.

A running simulation becomes paused; in any other state nothing changes.

Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.post('/simulation/step')
def step() -> dict:

Advance the active simulation by exactly one tick and leave it paused.

Works from idle, paused or running and does nothing once the incident is completed. If the fire goes out on this tick the simulation completes instead, and a city incident is recorded in the incident history.

Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.post('/simulation/tick')
def tick() -> dict:

Advance the active simulation by one tick if it is running.

Clients call this repeatedly to play the simulation (the UI paces the calls by the playback speed); when the simulation is not running nothing changes. When the fire goes out, a city incident is recorded in the incident history.

Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.post('/simulation/reset')
def reset() -> dict:

Reset the active simulation to its initial condition.

Goes back to tick 0 in the idle state with the starting fire (including ignitions added before the first tick) and re-seeds the random generator; spot fires and queued suppression are discarded. City scenarios also reset people, crews and the event log. The next run is recorded as a new incident.

Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.post('/simulation/speed')
def speed(body: SpeedIn) -> dict:

Set the playback speed of the active simulation.

The value is stored and reported as speed in the state payload. The server does not advance time on its own; the UI uses the speed as the number of ticks to request per second.

Arguments:
  • body: The new speed (0.25 to 16.0).
Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.get('/simulation/state')
def state() -> dict:

Get the live state of the active simulation.

Every /simulation endpoint except GET /simulation/map returns this same payload.

Returns:

A dict with state ("idle", "running", "paused" or "completed"), tick, speed, counts (number of cells per state: unburned, igniting, burning, burned, suppressed), grid (height rows of width cell-state codes: 0 unburned, 1 igniting, 2 burning, 3 burned, 4 suppressed), map_type, scenario (id and name), wind (direction the wind blows toward, in degrees from north, and speed in km/h), incident_id (id of this run's history record, or None until it is recorded) and city (for city scenarios the town's dynamic state: clock, population and building totals, per-asset arrays, priorities, crews, recent events and hazards; None for wildland).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.get('/simulation/map')
def simulation_map() -> dict:

The static map (land use, fuel, elevation, assets). Fetch once per scenario.

Wildland maps have no assets, fire station, crews or asset kinds, and their land use is derived from the fuel layer.

Returns:

A dict with map_type, width, height, cell_size_m (10), landuse, fuel and elevation (height rows of width values: land-use codes, fuel codes and elevation rounded to 3 decimals), assets (one dict per building, park or road segment with id, kind, name, street, x, y, w, h, floors, capacity, parts and occupants0, the people present at the start), station ({"x", "y"} of the fire station, or None), crews (id and name of each crew), hour and kinds (label, vulnerability and hazard of each asset kind).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.post('/simulation/ignite')
def ignite(body: CellIn) -> dict:

Start a fire at a cell. Before the first tick it becomes part of the scenario.

At tick 0 the cell is added to the scenario's ignition points, so resets and replays keep it; later it is a spot fire, which a reset removes.

Arguments:
  • body: The cell to ignite.
Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario or the incident is closed (reset first); 422 if the cell is outside the map or has nothing to burn.
@app.post('/simulation/suppress')
def suppress(body: SuppressIn) -> dict:

Queue suppression on cells (same effect as a bus suppression command).

The cells are treated on the next tick: those inside the map that are unburned, igniting or burning become suppressed, the others are ignored. The returned state does not show them yet.

Arguments:
  • body: The cells to suppress.
Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.post('/simulation/dispatch')
def dispatch(body: DispatchIn) -> dict:

Send the nearest available fire crew to an asset.

City scenarios only. The nearest free crew (city-block distance) travels there, then works at the asset for a limited number of ticks, suppressing fire in and around it and helping people get out.

Arguments:
  • body: The asset to protect.
Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 404 if the asset does not exist; 409 if there is no active scenario, it is not a city scenario, the incident is closed or no crew is available.
@app.post('/simulation/auto-dispatch')
def auto_dispatch(body: AutoDispatchIn) -> dict:

Turn automatic crew dispatch on or off.

City scenarios only. While it is on, before every tick the most urgent assets that no crew is assigned to get the nearest free crew, in priority order; low-priority assets are skipped. The change is written to the incident's event log.

Arguments:
  • body: Whether automatic dispatch should be on.
Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario or it is not a city scenario.
@app.post('/simulation/end')
def end_incident() -> dict:

Close the incident now and record it in the history (city scenarios).

The simulation becomes completed whatever its state. A city incident that has run at least one tick and is not recorded yet is saved with outcome "stopped", and its id appears as incident_id in the returned state. Wildland scenarios are only stopped.

Returns:

The live state payload (same shape as GET /simulation/state).

Raises:
  • HTTPException: 409 if there is no active scenario.
@app.get('/incidents')
def list_incidents() -> list[dict]:

List the incident history, newest first.

Each entry is a brief record without the per-tick timeline and key events; get them with GET /incidents/{incident_id}.

Returns:

One dict per incident (IncidentRecord.brief) with id, name, scenario_id, source, outcome, started_at, ended_at, ticks, params and summary (without timeline and key_events).

@app.get('/incidents/{incident_id}')
def get_incident(incident_id: str) -> dict:

Get one incident from the history, including its timeline and key events.

Returns the full record: run parameters, outcome and the complete summary (people, buildings, losses, key events and the per-tick timeline).

Arguments:
  • incident_id: Id of the incident.
Returns:

The full IncidentRecord as a dict: the same keys as a GET /incidents entry, with the complete summary.

Raises:
  • HTTPException: 404 if no incident has this id.
@app.delete('/incidents/{incident_id}', status_code=204)
def delete_incident(incident_id: str) -> None:

Delete one incident from the history.

Responds with 204 No Content.

Arguments:
  • incident_id: Id of the incident to delete.
Raises:
  • HTTPException: 404 if no incident has this id.
@app.delete('/incidents')
def clear_incidents() -> dict:

Delete every incident from the history.

Returns how many incidents were deleted.

Returns:

{"deleted": <number of incidents deleted>}.

@app.post('/incidents/simulate', status_code=201)
def simulate_incidents(body: BatchIn) -> list[dict]:

Run city incidents headless with varied conditions and record them.

Each run is a real simulation (random seed, wind, time of day, crews and response mode); the parameters are stored, so every run can be replayed.

The conditions are drawn from a generator seeded with seed: repeating a request with the same seed and settings gives runs with the same conditions and outcomes, and without a seed every request differs. The live simulation is not affected.

Arguments:
  • body: Number of runs, town size, tick limit per run and optional seed.
Returns:

One brief record per run, in run order (same shape as the GET /incidents entries), each with source "simulated" and outcome "extinguished" or "time_limit"; the response status is 201.

Raises:
  • HTTPException: 422 if the engine rejects a generated scenario.
def mount_ui( application: fastapi.applications.FastAPI, directory: str | os.PathLike[str]) -> bool:

Serve a built UI (the frontend/dist folder) from the root of an app.

Call it after every API route is registered: the mount answers only the paths the routes do not, and html=True serves index.html for /.

Arguments:
  • application: The FastAPI app to mount the UI on.
  • directory: Folder that holds the built UI (index.html and assets/).
Returns:

True if the folder exists and was mounted, False if it was skipped.
